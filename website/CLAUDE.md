# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev        # Start development server (Turbopack)
pnpm lint       # Lint + type-check (use this to verify changes, not pnpm build)
pnpm build      # Production build (only when explicitly needed)
```

Run all commands from the `website/` directory. Also run `npx tsc --noEmit` to catch type errors ESLint misses.

## Architecture

Next.js 16 (App Router) portfolio, React 19, TypeScript (strict), Tailwind CSS v4, pnpm. React Compiler is enabled (`reactCompiler: true`) — note the `react-hooks/immutability` and `react-hooks/set-state-in-effect` lint rules it adds (subscribe to media queries via `useSyncExternalStore`, mutate shared refs only in their owning component).

The site is an **editorial "newspaper-of-record"** redesign with three page types and a dark/light theme.

### Routes (`src/app/`)

- `/` — Home: masthead (fig.1 band canvas), `01 The Chapters`, `02 Selected Work`, `03 The Person`.
- `/record` — **The Record**: one filterable timeline of everything (73 entries), with the year-gutter constellation canvas + per-year "consensus" confirm animation. (Route lives at `src/app/record/`; the client lives at `components/record/record-client.tsx`.)
- `/record/[slug]` — **Case study** template. `generateStaticParams()` prerenders the **authored** cases (the record rows that carry a `case` detail); per-case `generateMetadata()`. Non-case projects have **no** detail page — they live in the record as plain timeline rows with external links.
- `/resume`, `/cv`, `/cover-letter` and `/<any of them>/[variant]` — the PDFs, **streamed** from Cloudinary (not 302'd). **All three are optional catch-alls** (`app/resume/[[...variant]]/route.ts` and siblings) and behave identically, so a résumé profile, a company cover letter or a future CV variant needs **no registration here** — publishing it upstream is the whole deployment. See "Documents" below.
- `/api/resume`, `/api/cover-letter` — the legacy paths, now 308s to `/resume` and `/cover-letter`. **Never delete them**: DNS forwards and long-shared links still arrive there, several of them cached as permanent redirects.
- `/api/health` — liveness probe (`{ success, timestamp, uptime, env, commit }`, `no-store`) for uptime monitors and post-deploy smoke checks. **Probes no dependency on purpose** — Neon and Spotify are both optional to the site, so a red healthcheck would mean nothing about whether the site renders. HEAD works too (Next aliases it to GET).
- `/linkedin-banner.png`, `/x-banner.png` — the profile banners, generated on demand. **Unlisted**: not linked, not in the sitemap (but deliberately *not* in `robots.txt` either — a `Disallow` would publish the path, same reasoning as `/arcade/stats`). See "Profile banners" below.
- `next.config.ts` `redirects()`: `/projects`, `/projects/:slug`, `/experiences` → `/record` (301). The old projects/experiences pages were removed. (The route was renamed from `/work` → `/record`; a record entry's `slug` maps to `/record/[slug]`.)

### Theme & tokens

- **`next-themes`** (`components/shared/theme-provider.tsx`): `attribute="data-theme"`, `storageKey="jagnani73-mode"`, `defaultTheme="system"` + `enableSystem` (follows the OS scheme; `light` paper is the fallback), themes `dark` (cyan) / `light` (paper), no-flash.
- Tokens are CSS custom properties in `src/app/globals.css`, defined per `[data-theme]` and mapped into Tailwind v4 via `@theme inline` → use utilities `bg-bg text-tx border-rule text-pri text-sig text-acc bg-pri-a18` etc. **Do not add unlayered element rules** (e.g. a bare `a {}`) — they override `@layer utilities` and break `text-*` on links. Keyboard focus shows a `:focus-visible` ring (`--sig`); the bare `outline: none` is paired with a `:focus-visible` override, never left standalone.
- Canvas/JS color access: `utils/constants/theme-tokens.ts` (typed token objects) + `hooks/use-theme-tokens.ts` (replaces the prototype's `window.PAGE_THEME`).
- Single breakpoint **1201px** via `@theme { --breakpoint-rail }` → `rail:` (≥1201 desktop) / `max-rail:` (≤1200 compact) variants. Prefer CSS variants over JS; `hooks/use-is-mobile.ts` only where JS needs the boolean.
- Fonts (`app/layout.tsx`, `next/font`): **Anton** (`font-display`), **Instrument Serif** (`font-serif`), **JetBrains Mono** (`font-mono`), **DM Sans** (`font-sans`).

### Content (`src/content/`) — typed, build-static

- `record.ts` — the single source: the 73-entry record + `getRecordCounts()` (built, never hardcoded). Case rows carry a `case: CaseDetail` (imported from `cases/*.tsx`), so **this module pulls all case bodies** — keep it **server-only**.
- `record-lib.ts` — **client-safe** record helpers/config (`FILTERS`, `kindColor`, `sequenceYear`, `yearHash`, `isCase`, `rowKey`), imports no case content. The interactive timeline imports from here; the heavy `RECORD` reaches the client only as case-stripped rows passed by `record/page.tsx`.
- `home.ts` — chapters / `PERSON` / deck (Selected Work is **derived**, not stored here). `PERSON` (typed `Person`) carries the italic `quote` (`pre`/`emphasis`), the `bio` (paragraphs as `BioSegment[]` runs — `em` marks the `text-tx` highlight), `arcadeCaption`, the 4-cell `currently` strip, `links` (github/linkedin/email — **no twitter row**), and `resume` (`/resume` — label carries no date, see "Documents").
- `cases/*.tsx` — each authored case's `CaseDetail` (the `/record/[slug]` content), imported into its `record.ts` row. `cases/index.ts` derives the registry (`getCase`/`getAllCaseSlugs`/`getCaseTitle`/`getNextSlug`/`getCaseImage`/`orderedSections`) from `RECORD` — there is **no `AUTHORED` map**.
- `metrics.ts` — hardcoded metric fallbacks.

### Types (`src/utils/types/`)

**Every** type lives here, one file per domain — `case.types.ts` (`CaseDetail` = the **authored** detail; `ResolvedCase` = what `getCase` returns, with the row-derived fields required; `CaseFigure` = the `fig` pair `{ component, alt }`; `Fig`; the `CaseSections` object + `CaseSection` render union), `record.types.ts` (`RecordEntry` — including `case?: CaseDetail` — `Kind`/`FilterId`), `theme.types.ts` (`ThemeTokens`/`ThemeName`), `home.types.ts` (`Chapter`/`SelectedWorkItem`/`Person`/`BioSegment`/`PersonLink`), `metrics.types.ts` (`Metrics`), `component.types.ts` (the `*Props` + `MarkMode`), `fig.types.ts` (`AgNode`/`NodeKind`/`FigAccent`/`JournalColor` — figs import the color keys `as C`), and the home-`03` island types — `arcade.types.ts` (`ArcadeGame`/`GameProps`/`GameMode`), `music.types.ts` (`MusicState`/`NowPlaying`/`TopTrack`/`MusicPayload` + the `Spotify*` Web-API wire shapes), `sky.types.ts` (`SkyLocation`). Modules/components import their shapes from here — **define new types in `utils/types/`, never inline.** Sole exception: `MarqueeProps` stays in `fig-marquee.tsx` (vendored verbatim from react-easy-marquee).

### Selected Work (home `02`) — derived, never curated

`utils/functions/selected-work.ts` `getSelectedWork(n=6)` returns the **latest N case studies, newest-first**, walking `RECORD` (internal `isCase` entries, already chronological). The thumbnail is the case's **first img plate** (`getCaseImage` in `cases/index.ts`); cases with **no img plate are skipped** so every row shows a real thumbnail (e.g. `solana-ml-dsa-44` has only code plates → it falls through and the next case down is pulled in). Per row: title/tag come from the case registry (`getCase`) — `tag` = the first `·`-segment of the case `badge`, lowercased, **except** `agent-sdk`/`goldrush-kit` whose tag is a live metric (`METRIC_BY_SLUG`). Adding an image-backed case to the record surfaces it here automatically.

### The Person (home `03`) — bio + three interactive islands

`components/home/person.tsx` (a Server Component) composes the section from `PERSON`: section head, the pull-quote + `bio` runs, the **Arcade**, a "currently" hairline strip, the off-the-clock media row (**MusicPanel** + **SkyMap**), and the contacts list. The three islands are `"use client"`:

- **Arcade** (`home/arcade.tsx` + `home/arcade-games.tsx`): a fixed-250px hub showing one game (picked at random post-mount) rendered with the **same bare `ArcadeCard` as the `/arcade` board** — no tagline, no shuffle CTA; just the game label + a MINE/YOU bests pair in the title row, and confetti + a WebAudio chime on a win/new-best. Six games (`reaction`/`memory`/`clicks`/`ttt`/`c4`/`wordle`) live in `arcade-games.tsx` with the `ARCADE_GAMES` registry; each is a `{ score, start, end }` playfield (`GameProps`) — `score(value, detail?)` records a best + emits telemetry, `start()` fires once on first engagement, `end(detail)` reports a terminal round that sets no best (a loss/draw/fail) — and the hub decides improvement by `mode` (`min`/`max`/`wins`). Every board game shares one layout — a uniform `SQUARE` board (cells derived to fill it) plus its control panel, centered together as a tight group (not stretched into equal halves); Reaction is the full-bleed exception. The MINE/YOU bests sit in the card header (right of the title), not a footer. The home hub renders `ArcadeCard` centered in the right half of the statement row (`max-w-[480px]`); the `/arcade` all-games board renders it via `.arcade-card-w` — **capped at 480px at every width** (single CSS rule, no breakpoint), shrinking to the viewport only on narrower screens. **Responsiveness lives entirely in CSS** (`globals.css`): the playfield (`.arcade-play`) is a `container-type: inline-size` query container with `min-height` (so the card grows to fit), and the board+panel row (`.arcade-game-row`) is the horizontal `[board | panel]` group on a wide card but **stacks board-over-panel via `@container (max-width: 470px)`** on a narrow card (phone) — so nothing overflows and there's no JS measuring/scaling. The full-bleed Reaction sits outside `.arcade-game-row` and uses `PLAY_MIN_H` (kept in sync with `.arcade-play`'s `min-height`) to fill the content-driven playfield. Bests persist via **`hooks/use-stored-best.ts`** (a `useSyncExternalStore` store, **not** a read-in-effect) under `arcade.best.<gameKey>` — **never rename those keys**. `MINE` values in the registry are **placeholders** (owner inputs pending). Game/chrome colors are CSS `var()`s so the arcade flips with the theme; the confetti reads real hex via `useThemeTokens`. The opening game is randomized in a single post-mount `setState` (a random index during render would hydration-mismatch). **Analytics** (`utils/functions/analytics.ts`): the card emits three GA4 events through `sendGAEvent` (`@next/third-parties/google`) into the existing `GoogleAnalytics` property (`layout.tsx`) — `arcade_view` (fired once when the card scrolls into view, via a dedicated `IntersectionObserver` so the below-fold home arcade isn't over-counted), `arcade_start`, and `arcade_play` (params: `game`/`mode`/`page`/`outcome`/`score`/`new_best`/`moves`/`first_word` + session `session_plays`/`win_streak`, the latter two module-scope counters). `page` (`ArcadePage` = `"home"`/`"arcade"`, an `ArcadeCardProps` field) tells the home-page arcade apart from the `/arcade` board. GA4 is gated on `process.env.NODE_ENV === "production"` so `pnpm dev` sends nothing; to slice by the custom params in GA4 they must be registered as custom dimensions in the GA UI. **Dual sink:** alongside GA4 the card also beacons every event to its own **Postgres sink** powering the _undisclosed_ `/arcade/stats` dashboard — the layer that expresses records/distributions/per-visitor superlatives GA4 can't (GA4 only sums/counts/averages and caps cardinality). `analytics.ts` emits to both (`sendGAEvent` + `navigator.sendBeacon` → **`app/api/arcade-event/route.ts`**), carrying the GA params plus `duration_ms` (round length, captured centrally in `arcade-card.tsx` from the last `start()` — only the round right after a start() gets one), an anonymous persistent `visitor_id`, an ephemeral `session_id`, and a `dnt` flag. The route validates against allowlists, **drops spoofed sub-floor record scores** (`MIN_SCORE`, e.g. reaction ≥ 80ms — one forged row would own an all-time record forever), and appends one immutable row to **`arcade_events`** (Neon Postgres; canonical DDL in `db/schema.sql`, applied via `pnpm db:apply` (`scripts/apply-schema.ts`); events are append-only and "cool stats" are _queries_, so new metrics need no migration — the `detail` jsonb column is **reserved** for future per-game signals, nothing writes it yet). DB layer: a **typed Drizzle client** (`utils/functions/db.ts` → `drizzle-orm/neon-http` over `@neondatabase/serverless`, `server-only`, `db` null when unconfigured) bound to a schema **generated from the live DB** — `pnpm db:pull` (`drizzle.config.ts`, uses `DATABASE_URL_UNPOOLED`) introspects Neon into **`src/common/database/`**: `schema.ts` (the `arcadeEvents` table) + `database.types.ts` (`ArcadeEvent` / `NewArcadeEvent`, inferred via `InferSelect/InsertModel` — so row/insert types can't drift from the table). jsonb columns can't be inferred, so they're hand-typed in `jsonb.types.ts` (`ArcadeDetail`) and applied via `.$type<>()` in `schema.ts` (**re-apply after a `db:pull`** — pull resets it to `unknown`). The route inserts through the typed schema (`db.insert(arcadeEvents).values({…})`), not raw SQL. **Privacy gating:** the persistent `visitor_id` (localStorage `arcade.vid`, via **`utils/functions/visitor.ts`**) is suppressed for opt-outs (GPC/DNT) and privacy-gated geos (EU 27 / EEA / UK — **`utils/constants/privacy.ts`**); the client decides from the coarse `arc_geo` cookie that **`src/proxy.ts`** (Next 16's renamed `middleware`, Node runtime, scoped to `/` + `/arcade`, set once so repeat loads stay cacheable) writes from `x-vercel-ip-country`, and the route **re-enforces it server-side**. Gated visitors still count toward aggregates/records — only the per-visitor superlatives need the id. The sink **write** is additionally limited to the real production deploy (`VERCEL_ENV === "production"` in the route) so Preview traffic can't pollute the stats. Env (server-only): `DATABASE_URL` + `DATABASE_URL_UNPOOLED` (Vercel Neon integration; mirrored to `.env.local`). **The `/arcade/stats` dashboard** (`app/arcade/stats/page.tsx` — Server Component, `revalidate: 60`, `noindex`, **unlisted**: not linked or in the sitemap; deliberately _not_ in `robots.txt` since a Disallow would publish the path) reads through `utils/functions/arcade-stats.ts` (`getArcadeStats()` — one batched fan-out of Drizzle aggregate queries; counts cast `::int`, sums `::float8` so Neon returns JS numbers; **never throws** → quiet fallback on error/empty) and renders four groups: at-a-glance totals + view→start→play funnel, favourite games (bars), records & bests (featured fastest-reaction + per-game bests by `mode` + longest streak), Wordle openers (first-letter % + top words), per-visitor superlatives (anonymised `#xxxx` labels). Server-safe game label/unit live in `utils/constants/arcade-meta.ts` (the `ARCADE_GAMES` registry is client-only, so it's mirrored — keep in sync); result types in `utils/types/arcade-stats.types.ts`. **Data only appears after a production deploy** (the sink write is prod-gated), so until then the page shows its empty state.
- **SkyMap** (`home/sky-map.tsx`): a realtime, draggable alt-az star map (stereographic, ~112° FOV, 10h trails, N/E/S/W marks, speed control, geolocation). It is **theme-aware** via `useThemeTokens()` (`tokens` is a `drawAt` dep): **dark** mode is the fixed night scene drawn from the live dark token palette (via `useThemeTokens`; `THEME_TOKENS` is imported only as the light/dark discriminator, never as a color source); **light** mode is a **flat paper sky with ink stars** — the panel tone (`--panel`) stays constant and stars/trails/lines render at full visibility, with **no sun and no day↔night blend**, so the time-lapse never washes out. Light stars use a fixed dark→muted ink ramp (`LIGHT_STAR` = `#16191C`/`rgba(42,58,72,…)`/`rgba(78,98,114,…)`, by magnitude, no bright-star glow), the bg starfield is a toned-down slate (`LIGHT_BG_STAR`, ×0.45 alpha), constellation lines are `--pri` @ .5, trails are `--pri` .05→.25, and the ground is a `--bg` dim gradient (now shared with dark — single branch). Card chrome always uses live theme vars. Off-palette horizon-line fill comes from a token hex via the shared `hexRgb()` helper in `utils/functions/canvas.ts`. Gated on `use-reduced-motion` (no auto-advance) and `use-in-view` (rAF pauses offscreen); the header clock is `suppressHydrationWarning`. The canvas wrapper is `h-[188px]` on mobile but **`rail:flex-1` with a `rail:min-h-[210px]` floor** on the desktop two-up row, so the map grows into whatever height MusicPanel sets beside it instead of leaving dead panel below the controls; `drawAt` re-reads `clientWidth/clientHeight` every frame, so the canvas follows without a ResizeObserver.
- **MusicPanel** (`home/music-panel.tsx`): "on rotation" — now-playing (→ last-played fallback) hero, the 4-week top-tracks shelf, and a **hand-picked playlist strip**, fed by the **`app/api/spotify/route.ts`** route handler (the Spotify secret stays server-side). The route mints a short-lived access token from `SPOTIFY_REFRESH_TOKEN` (module-cached until ~expiry), then returns normalized `{ configured, now, top, playlists }`; the client polls every 60s. The **playlists are curated by id only** — `SPOTIFY_PLAYLIST_IDS` in `utils/constants/site.ts`, in display order (it lives there, not `content/home.ts`, so the route doesn't pull the case registry into its bundle); name, cover and track count are read live per request (`GET /playlists/{id}?fields=…`, `revalidate: 3600`, batched into the same `Promise.all` as the now/recent/top calls) so a rename or an added track can't drift. A playlist that 404s drops out of the strip instead of taking it down. **They must stay public** — the token carries only `user-read-currently-playing user-read-recently-played user-top-read`, so a private one would need a `playlist-read-private` re-mint. The strip renders as **full-width rows in the top-tracks rhythm** (32px cover + name left, track count right, hairline between) — not a 3-up grid, which on the ~936px desktop panel strands each item in dead space and shrinks the cover to mush. Without the Spotify env vars the route reports `configured: false` and the panel shows a neutral idle fallback. Env (server-only): `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET`/`SPOTIFY_REFRESH_TOKEN` — mint the last one once via **`scripts/spotify-refresh-token.ts`** (Authorization-Code consent; redirect `http://127.0.0.1:3000/callback` — stop the dev server first, it shares port 3000; override via `SPOTIFY_REDIRECT_URI`). Spotify exposes **no personal play counts**, so the shelf shows track + artist, not a "plays" number. The now-playing equalizer uses the `eqBar` keyframe / `.eq-bar` class in `globals.css`.

RNG for all of the above goes through `utils/functions/random.ts` (`rnd`/`rndf`/`rndBetween`) — module-scope so `Math.random()` never sits in a component body (React Compiler purity rule).

### Case studies — rows of the record

**The record is the single source.** An authored case is a `record.ts` row with a `case: CaseDetail` attached; `CaseDetail` holds only the detail (`badge`, `deck`, `fig` (a `CaseFigure` = `{ component, alt }`), `sections`, `seoDescription`, optional `displayTitle`/`docName`) — **not** `slug`, `title`, or roster position, which come from the row (the authored type no longer includes them, so it's compiler-enforced). `getCase(slug)` merges them and returns a **`ResolvedCase`**: the detail with `title` (`= case.displayTitle ?? row.title`), the derived `docTitle` (`` `${docName ?? title} — Case Study` ``), `slug`, and `idx`/`rosterSize` all required — **never authored**. The **roster is record order**: `cases/index.ts` filters `RECORD` to rows with a `case`, in array order → that drives `idx`, `rosterSize`, and `getNextSlug` (the plates-section "next study" CTA, wraps). Every page — Home, The Record, and case studies — shares one **`MastheadBar`** (top bar) and one **`PageFooter`** (a 3-column desktop grid — copyright + astro line | the **`FooterArcadeCta`** | back-to-top — so the centre CTA is anchored dead-centre via `col-start-*`, not flex; the arcade CTA is a `"use client"` gate that hides on `/arcade` and is the **sole entry point** into the otherwise-unlisted board), both **rendered once by `PageShell`** (the bar above `{children}`, the footer after — so individual pages/mastheads no longer invoke either); each carries `relative z-[1] bg-bg` to stay opaque over The Record's fixed constellation. The bar is a client component: `STATUS` sits right on every page and the `jagnani73` brand sits left on desktop only (mobile shows it in the `SiteRail`); the centered CTA is chosen from `usePathname()` — home → `the record`, `/record` (and the unlisted `/arcade`) → `the front page`, a case (`/record/[slug]`) → `the record` (the arrow glyphs are `CtaTerm`'s: `→` forward, `←` back). Cases carry their case-to-case "next study" CTA in the plates section instead (`PlateViewer`, stacked above the external "source" link; both are `CtaTerm`s, so the data labels carry no arrow glyph). Set `displayTitle` only when the masthead name differs from the timeline title (e.g. row "Solana ML-DSA-44 fork" → `displayTitle: "ML-DSA-44"`; "BharatBeacon" → "Bharat Beacon"); the H1 is uppercased via CSS. Each case carries its **fig.1 directly** — `fig: { component: FigDao, alt }` (the component imported in the case file, paired with its screen-reader label as a `CaseFigure`) — so the masthead renders `c.fig`; there is **no fig registry or `FigKind` enum**. **`sections` is an object keyed by type** (`split`/`arch`/`cards`/`stats`/`plates`, each at most once) — **insertion order = render order**; `orderedSections` tags each entry into the `CaseSection` render union. `SLUG_ALIASES` maps `ai-agent-sdk` → `agent-sdk` so the legacy URL still resolves. **Every non-case project is just a timeline row** (external `url`, no `case`).

### Live metrics (ISR)

`utils/functions/fetch-metrics.ts` `getMetrics()` fetches GitHub stars/forks + npm version count at build (`revalidate: 86400`), falling back to `content/metrics.ts` — **Server Components only**, never client-side, never renders a blank/spinner.

### SEO

`utils/functions/seo.ts` is the single source of truth: `SITE_URL`/`SITE_NAME`/`SITE_DESCRIPTION` (imported by `layout.tsx` — don't redeclare) + JSON-LD builders (`personLd`, `websiteLd`, `caseLd`, `collectionPageLd`, `breadcrumbLd`). `components/shared/json-ld.tsx` renders blobs into `<script type="application/ld+json">` (escapes `<` → `<`). **Where JSON-LD lives:** home (`page.tsx`) → `Person` + `WebSite`; `/record` → `CollectionPage` + `BreadcrumbList`; each case → `CreativeWork` + `BreadcrumbList` (refs the Person by `@id`). `app/sitemap.ts` + `app/robots.ts` are file-convention routes (sitemap walks `getAllCaseSlugs()`; robots disallows `/api/`). Root `layout.tsx` sets a title **template** `"%s — Yashvardhan Jagnani"` and `alternates.canonical` — so page-level `title`s are the **bare** page name (no manual suffix) and each page sets its own `canonical`. **Case descriptions:** authored cases' `deck` is JSX, so each authored case carries a plain-text `seoDescription` (~150 chars); `generateMetadata` prefers it, then a string `deck`, then a generic fallback. Add `seoDescription` whenever you add an authored case. **OG images:** there are **no per-case OG overrides** — the file-convention `app/opengraph-image.tsx` (one branded card) is applied by Next to every route. Its contour backdrop is generated from the shared `utils/functions/contours.ts` and its `STATUS` line from `site.ts`, so the card stays in lockstep with the live masthead; remote fonts are fetched with an `res.ok` check that logs CDN failures. The case `CreativeWork` JSON-LD still gets an `image`, derived from the case's first img plate (`getCaseImage`).

### Canvas islands (`src/components/canvas/`, all `"use client"`)

`band-canvas.tsx` (home contours), `time-constellation.tsx` (`/record` mesh), `figs/{fig-score,fig-agent-graph,fig-wager}.tsx` (case fig.1). All gate on `hooks/use-reduced-motion.ts` (static end-state) and pause when offscreen (`IntersectionObserver` / `hooks/use-in-view.ts`). The two true `<canvas>` islands (`band-canvas`, `time-constellation`) share their whole lifecycle — element/DPR/resize/rAF/offscreen-pause/teardown — via **`hooks/use-canvas-scene.ts`** (each supplies a `setup → draw(frame)`); the marching-squares contour geometry comes from **`utils/functions/contours.ts`** (shared with the OG card so the two can't drift), and small DPR/`rgba` helpers from `utils/functions/canvas.ts`. Year-confirm lives in `components/record/{year-mark,consensus-block}.tsx`. Lightbox in `components/case/plate-viewer.tsx` (focus-trapped `role="dialog"`). The home-`03` canvases (`home/sky-map.tsx`, the arcade confetti in `home/arcade.tsx`) live in `home/` and own their own loops (they don't use `use-canvas-scene`) but follow the same `use-reduced-motion` + `use-in-view` discipline — see "The Person" above. Shared fig "card" surface: `figs/fig-style.ts` (`figPanel(t)`); each case passes its `fig` (a `CaseFigure` — component + `alt`) directly via the case data, and `case-fig.tsx` wraps it `role="img"` with that label.

### Component layout (`src/components/`)

`shared/` (theme-provider, site-rail, page-shell, masthead-bar, page-footer, cta-term, back-to-top), `home/` (masthead, chapters, selected-work, **person** + its islands `arcade`/`arcade-games`/`sky-map`/`music-panel`), `record/`, `case/`, `canvas/`. **Every call-to-action uses one shared `CtaTerm`** (`shared/cta-term.tsx`, styles in `globals.css` → `.cta-term`): a bracketed mono label with a sliding arrow (`arrow` glyph, default `→`, + `arrowSide` `"left"`/`"right"`); `external` switches between a next/link and a target-blank `<a>`, and omitting `href` renders a plain `<span>` (for a badge inside an already-clickable row). **The arrow is the component's — data labels (case `cta.label`, `PERSON.resume.label`) carry no arrow glyph.** Used by the section-head notes (chapters → the full record, selected work → case studies), the person résumé link, the `MastheadBar` center CTA, the plates "next study" + "source" links, and the record timeline's **case-row badge** (`CASE STUDY →`, a non-link span via the compact `.cta-term--sm` variant, shown in place of the kind label when `isCase(r)`) — so restyling CTAs is a single-file change.

### Profile banners (`/linkedin-banner.png`, `/x-banner.png`)

Both banners share the site's palette and geometry rather than reimplementing them — same argument `contours.ts` already makes for the band and the OG card. **`utils/functions/banner.tsx`** owns both: `BANNER_VARIANTS` (five LinkedIn compositions — `a-masthead`/`b-safe`/`c-dark`/`d-quiet`/`e-centred`, on the contour field) and `X_BANNER_VARIANTS` (`x-line`/`x-bare`, on the **real star map**), plus `renderBanner()` / `renderXBanner()`, which return an `ImageResponse`. Types are in `utils/types/banner.types.ts`. **Three consumers import this module and must never fork it**: the two route handlers and `scripts/linkedin-banner.tsx` (writes every variant to disk for side-by-side comparison; `pnpm tsx scripts/linkedin-banner.tsx <outDir> <scale>`).

**The X header draws the same sky as the home page.** The star catalogue, constellation pairs, seeded background field and the alt-az → stereographic projection live in **`utils/functions/sky.ts`**, imported by both `home/sky-map.tsx` (canvas, redrawn per frame) and `banner.tsx` (traced once into SVG) — the `contours.ts` pattern applied to the sky, so the two can't drift. `makeProjector(w, h, alt, az)` is the single camera; `makeBgStars(count, seed)` generates the procedural filler (the card uses 320, the 3:1 header needs ~2400 since a wide crop only catches a slice of the sphere). The header's instant/place/facing are **fixed constants** chosen by scoring candidates for how much of the catalogue lands in frame — looking east from Singapore at 22:00 UTC gives 17 catalogued stars and 6 constellation segments, against 8 and 3 facing north. **Anything stated in the banner text about the sky must be derived, never typed**: `x-line`'s latitude comes from `formatLat(X_SKY_LOC)`, so it cannot describe a sky the image isn't showing (an earlier hardcoded "looking north" silently became wrong the moment the camera turned east).

**Design units, not pixels.** The banner is authored at `BANNER_W`×`BANNER_H` = 1584×396 — LinkedIn's *layout* size — and every value is multiplied by `scale` at render time (`const s = (n) => n * scale`). Never render at 1x: LinkedIn displays the banner ~1128 CSS px wide, so a high-DPI screen wants ~2256 device px and a 1x file gets upscaled. `DEFAULT_SCALE` is 3 (4752×1188, ~965 KB). The contour backdrop is emitted as **SVG with a `viewBox`**, so one trace in design units stays vector-sharp at any scale instead of re-tracing at a finer cell.

`BANNER_SAFE` records LinkedIn's conservative crop (centre 1350×220 → x 117–1467, y 88–308); variants differ mainly in whether their text clears it (`b-safe`, `d-quiet` and `e-centred` do; `a-masthead` and `c-dark` put the footline below it). The type column starts at x=470 in every non-centred variant because **the profile avatar overlaps the lower-left corner**.

The routes (`app/linkedin-banner.png/route.tsx` and `app/x-banner.png/route.tsx` — directory names containing a dot are valid route segments) are **dynamic on purpose** so `?variant=` and `?scale=` work, with `s-maxage=31536000` so each combination rasterises once and is then served from the CDN until the next deploy purges it. **`scale` is validated through the shared `parseScale()`** to whole numbers 1–`MAX_SCALE` (4) — it is caller-controlled and drives the raster size, so an unbounded value is an OOM; it lives in `banner.tsx` rather than in each route so the bound can't diverge. Unknown variants and out-of-range scales return 400 with a plain-text reason. Fonts come from jsdelivr with an `res.ok` check (same failure mode as the OG card) and are **module-cached**, with the cache cleared on failure so a warm function retries instead of serving a stuck rejection.

### Documents (`/resume`, `/cv`, `/cover-letter`, + variants)

The PDFs are built from LaTeX by the sibling private repo **`cv-cl`**, which publishes each one to a Cloudinary `raw` public_id on every push: `cv-cl/<slug>.pdf`, where the slug is the category (`resume`, `cv`, `cover-letter`) for its default and `<category>-<variant>` for a variant (`cv-cl/resume-blockchain.pdf`, `cv-cl/cover-letter-circle.pdf`). Nothing in this repo builds or stores a PDF; the URLs are stable and always hold the current build.

**`DOCUMENTS` in `utils/constants/site.ts` is the one place that decides where a document lives** — upstream slug, served path, bracket label — alongside `DOCUMENT_BASE` (the `cv-cl/` folder URL, **trailing slash load-bearing**) and `DOCUMENT_OWNER`. The route handlers, the legacy `/api/*` redirects and `PERSON.resume` all read it, so moving a document is one edit. There are no per-document URL constants any more (`RESUME`/`CV`/`COVER_LETTER` are gone): a URL is `DOCUMENT_BASE` + slug + `.pdf`, derived in one place.

**Categories are closed; variants are open and deliberately unlisted.** All three categories are optional catch-alls (`[[...variant]]`) — and a static route file and its catch-all sibling **cannot coexist**, which is why there is no `app/resume/route.ts`, `app/cv/route.ts` or `app/cover-letter/route.ts`. `/cv` has no variants published today, but that is a fact about the upstream and gets no special case in the code (Squarespace path forwarding on `cv.jagnani73.com` reaches the catch-all too, so the three had better agree). Adding a résumé profile, a company letter or a CV variant is a publish in `cv-cl` and **zero edits here**. **Never add an allowlist of variants**: a list of company slugs committed to this public repo is a permanent record of every company applied to, which is exactly what the split-out cover letters exist to avoid.

Three rules make a request-derived slug safe, and all three are in `document-route.ts`:

1. **Validate the decoded segment before it touches any URL** — `^[a-z0-9]+(?:-[a-z0-9]+)*$`, ≤ 64 chars, and **exactly zero or one segment**. `/resume/a/b` is a miss and is never `join("-")`ed. Next splits the path on `/` *before* percent-decoding, so a `%2F` (or `%5C`) arrives as a literal slash *inside* one array element; the class excludes `/ \ . % : ,`, so `..` cannot form and no scheme or host can be spelled. Validate as received — decoding a second time is how `%252F` becomes a real separator.
2. **Assert the final URL after normalisation** — `new URL()`, then `href.startsWith(DOCUMENT_BASE)`. Checking the pre-normalisation string is the bug: `…/cv-cl/../../image/fetch/…` starts with the base right up until the parser collapses the dot segments. (Verified: four `../` in the segment resolves to `…/jagnani73/raw/image/fetch/…` and fails the check.) Defence in depth behind rule 1, not a substitute.
3. **Split the failure branch by cause.** An upstream **404** on a *variant* is a genuine absence → **302 to the category default** with `Cache-Control: no-store`. A bad-shape segment is the same miss. Anything else — 5xx, 401, timeout, non-PDF type — is a **502**. **The category default 404ing is a 502, never a redirect**: the target would be the path being requested, i.e. a loop.

**The miss redirects; it does not stream the default.** An unbounded set of made-up paths each streaming ~250KB would drain Vercel Hobby's 10GB Fast Origin Transfer in ~40k requests, and exceeding that disables the whole site for 30 days. A redirect costs a few hundred bytes and lands on a path the CDN already holds. 302 rather than 308 because the variant may be published tomorrow, and `no-store` so a transient miss cannot be cached against that path.

**The download name carries the variant, title-cased from the slug** — `Yashvardhan Jagnani [Resume - Blockchain].pdf`, `… [Cover Letter - Circle].pdf`. ⚠️ **That naming rule now lives in two repositories and they have to agree.** The scheme originates in `cv-cl`'s `scripts/Publish-Release.ps1`, which title-cases the same slug into the same bracketed label; the one deliberate difference is the date, which the sibling's on-disk name carries and this download name does not.

`utils/functions/document-route.ts` holds the single factory, `documentRoute(category)`, used by all three route files. **There is no fixed-route variant of it** — a second factory is how one category starts behaving differently from the others. It **streams** rather than 302ing, so the URL stays on this origin, the download name is ours, and `Referrer-Policy` actually applies. Load-bearing details:

- **Guard before streaming.** A missing Cloudinary *raw* public_id answers **404 with `Content-Type: image/gif`** and an `X-Cld-Error` header — a real GIF body. So the handler requires `res.ok` **and** an `application/pdf` upstream type, else 502 + `Cache-Control: no-store`. Never fabricate a 200. (That 404 is the one status a *variant* reads as "not published" instead — rule 3 above — and it is checked before this guard, since the guard cannot tell absent from broken.)
- `AbortSignal.timeout(10s)` on the fetch. undici's own is ~305s, past Vercel's 300s ceiling, so without it a dead origin burns the whole budget.
- `Content-Disposition` carries **both** `filename=` (ASCII-folded, quoted) and `filename*=UTF-8''…` (RFC 6266 §4.3) — `curl -OJ` and several download managers ignore `filename*` and fall back to the URL basename. The `rfc5987` helper also escapes `' ( ) * !`, which `encodeURIComponent` leaves alone; an unescaped `'` truncates the name at the parser.
- **The download names carry no date** (`Yashvardhan Jagnani [Resume].pdf`, `… [Resume - Blockchain].pdf`). The path always resolves to the current build, so a date would be a claim the URL cannot keep. Same reason `PERSON.resume.label` lost its "aug 2026".
- `Cache-Control: public, max-age=0, must-revalidate, s-maxage=300` — **no `stale-while-revalidate`**: Vercel honours it and it would let a viewer receive a PDF up to a day old, contradicting the 5-minute bound.
- Upstream `Content-Length` is forwarded only when there is no `content-encoding` — `fetch` decompresses transparently, so a forwarded compressed length would truncate the download.
- **No `dynamic`/`revalidate` export.** Next's cacheable-route template buffers the body via `.blob()`, which defeats the streaming; the Next 15+ default (GET handlers dynamic) is what's wanted. `next build` must show these as `ƒ`. Never `runtime = "edge"` — removed in Next 16.3.

**Not in `robots.txt`.** A `Disallow` is never crawled, so the `X-Robots-Tag: noindex, nofollow` on the response would never be read and the bare URL could still surface — same reasoning as `/arcade/stats`. Let the header do the work. (Note the standing `Disallow: /api/` does cover the *legacy* `/api/resume` path, so a crawler won't follow that 308.)

## Adding/Updating Content

- Record rows: `src/content/record.ts` (counts recompute automatically).
- A new full case study (**2 edits**): (1) add `src/content/cases/<slug>.tsx` exporting a `CaseDetail`, and (2) add its `record.ts` row with `slug` + `case: <import>`. The row's position in `RECORD` sets the roster index; the row owns `title`/`meta`. Set a plain-text `seoDescription` (~150 chars) — the JSX `deck` can't be used as a meta description. Set `displayTitle` only if the masthead name differs from the row title; `docName` only if the SEO name differs again. Author `sections` as a keyed object (`split`/`arch`/`cards`/`stats`/`plates`, in display order); every plate needs a `cap`. For a fig.1, write the component in `components/canvas/figs/`, then `import` it into the case file and set `fig: { component, alt }` (the `CaseFigure` pair — the component + its screen-reader label). **Don't put `slug`/`title`/`idx`/`rosterSize`/`docTitle`/`next` on the detail** — they come from the row or are derived in `getCase`/`getNextSlug` (the authored `CaseDetail` type omits them, so TypeScript enforces this). Non-case projects get **no** detail page — add them as rows with an external `url` and no `case` (only authored cases appear in `sitemap.xml`).
- A new résumé profile, per-company cover letter or CV variant (**0 edits here**): publish it from the `cv-cl` repo as `cv-cl/<category>-<variant>.pdf` and it is live at `/<category>/<variant>`. Don't register it, don't list it, don't link it — an unpublished slug 302s to the category default, which is the intended behaviour for a link that has gone stale. Only a *new category* touches this repo (`DOCUMENTS` + a route file).
- Home sections: `src/content/home.ts` (chapters / `PERSON` / deck). Edit the bio/quote/currently-strip/contacts via `PERSON` (the `bio` is `BioSegment[]` runs — set `em` to highlight a phrase). Selected Work isn't edited here — it auto-tracks the latest case studies in `record.ts` via `utils/functions/selected-work.ts`. Metric numbers/fallbacks: `src/content/metrics.ts`. Arcade `MINE` bests live in the `ARCADE_GAMES` registry (`home/arcade-games.tsx`); the music panel goes live once `SPOTIFY_REFRESH_TOKEN` is set (mint it via `scripts/spotify-refresh-token.ts`).
